# По порядку — итоговая работа

Автор: **Коряушкин Кирилл Русланович**, Moodle: **pepe1az**. Приложение: **https://8517.simple-server.tech:9443/**.

## Решение

Это индивидуальный список дел на Express и PostgreSQL. Пользователь вводит полученный отдельно токен, видит сведения автора, выбирает группу дел, добавляет записи, меняет названия, отмечает выполнение и удаляет ненужное. Группа соответствует полю runId; начальное значение — manual. Обязательное персональное дело «Итоговая работа 24.10.2026: pepe1az» создано через интерфейс и сохранено в базе.

Выбран уже используемый собственный VPS: новая покупка не потребовалась, доступны администрирование PostgreSQL и выделение ограниченных ролей. Это не бесплатный облачный тариф: стоимость существующего сервера несёт владелец. Отдельный HTTPS-порт сохраняет предыдущие учебные приложения. Nginx завершает TLS, systemd запускает Node.js и перезапускает процесс после сбоя. PostgreSQL принимает внешние подключения преподавателя только по TLS; приложение подключается локально.

Структура разделяет HTTP-маршруты, валидацию и SQL-запросы. Модуль store использует параметризованные запросы, фильтрует данные по настроенному автору и читает актуальное состояние базы при каждом обращении. Интерфейс написан на обычном JavaScript без сборщика. Данные не кэшируются в памяти приложения. Такой выбор упрощает воспроизведение и независимую проверку изменений.

## Данные и защита

Сервер назначает UUID, ownerLogin, время создания и начальное done=false. Время возвращается строкой UTC ISO 8601. POST принимает только title/runId, PATCH — непустой набор title/done. Название обрезается по краям; допустимы 1–200 символов Unicode. runId содержит 1–64 латинских буквы, цифры, дефисы или подчёркивания. Неверные типы, UUID, JSON и лишние поля отклоняются.

Все маршруты API защищены Bearer-токеном; публичен только маршрут логина и статический интерфейс. Токен хранится в памяти страницы до обновления, не помещается в URL, localStorage или исходники. Ошибки имеют единственный ключ error: неверный ввод — 400, авторизация — 401, отсутствующее дело — 404, недоступная БД — 503. Удаление возвращает 204 без тела.

## Запуск и проверка

Использованы Node.js **24.22.2**, PostgreSQL **16.15**, Ubuntu **24.04**. Точные зависимости закреплены lock-файлом. Для нового окружения выполните команды ниже; миграции запускает администратор, приложение работает ограниченной ролью. Заполните локальный .env по образцу, задайте длинный случайный токен и точные сведения автора. Не включайте этот файл в архив или репозиторий.

Проверены 46 HTTPS-запросов, независимые операции SQL, ограничения роли, браузерный CRUD и мобильная вёрстка. Реальное отключение PostgreSQL даёт 503; персональное дело сохраняется после перезапуска БД и приложения. Подробности находятся в docs/TEST-REPORT.md. Скриншоты показывают интерфейс, но не заменяют доступ к данным.

Проверяющему подготовлено прямое TLS-подключение к этой же таблице с отдельным паролем и правами только на учебные данные. Проверяются сертификат и имя сервера; незашифрованный внешний доступ запрещён. Реквизиты передаются только личным сообщением Moodle. SSH-туннель сохранён как дополнительный вариант. Архив содержит исходники, SQL, конфигурационные образцы и тесты, но не действующие секреты. Приложение необходимо оставить работающим до завершения проверки.
