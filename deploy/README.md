# Развёртывание

`nginx.conf` и `pepelaz-todo.service` — конфигурация работающего экземпляра, без секретов. Порт приложения 8090 доступен только на loopback; HTTPS — 9443. На другом сервере замените имя домена, пути к сертификату и установленному Node.js.

1. Скопируйте проект в `/opt/pepelaz-todo`, выполните `npm ci` с Node.js 24.
2. Создайте отдельную PostgreSQL-базу и примените SQL из README от администратора.
3. Создайте `/etc/pepelaz-todo.env` по `.env.example`, задайте реальные переменные, установите права `0600 root:root`. `EnvironmentFile` загружает systemd, приложение не получает права читать чужие файлы.
4. Установите unit, выполните `systemctl daemon-reload` и `systemctl enable --now pepelaz-todo`.
5. Настройте сертификат, установите nginx-конфигурацию, выполните `nginx -t` и reload. Разрешите входящий HTTPS-порт в firewall.
6. Для преподавателя выделите отдельную SQL-роль только с CRUD над `tasks`, ограничьте число соединений и время запросов. Прямой внешний доступ разрешите только этой роли, только к учебной БД и только через `hostssl` с SCRAM-аутентификацией. Приложение продолжает подключаться через loopback.
7. Дополнительно можно сохранить SSH-туннель: используйте отдельную системную учётную запись без оболочки. Ограничьте `AllowTcpForwarding local`, `PermitOpen 127.0.0.1:5432`, `PermitListen none`, `PermitTTY no`, `AllowAgentForwarding no`, `X11Forwarding no`, `ForceCommand /bin/false`. В authorized_keys допустим только выделенный ключ с `restrict,port-forwarding,permitopen="127.0.0.1:5432"`. До перезагрузки SSH обязательно выполните `sshd -t`.

8. На работающем экземпляре по запросу владельца открыт публичный TCP-порт PostgreSQL. TLS использует сертификат того же домена, что и сайт. Копия ключа PostgreSQL имеет владельца postgres и права 0600; сертификат и ключ обновляются deploy-hook Certbot с reload PostgreSQL. Минимальная версия TLS — 1.2. Проверка клиента — sslmode=verify-full с доверенным CA. Пять подключений на роль, statement_timeout=15s, idle_in_transaction_session_timeout=60s.
9. После изменения pg_hba.conf проверьте отсутствие ошибок через pg_hba_file_rules. После открытия порта проверьте извне успешный TLS-вход и отказ для незашифрованного соединения, другой БД и роли приложения.

Пароль роли, имя БД и конкретные параметры подключения передаются преподавателю отдельно. Секретов в этих конфигурационных образцах нет. SSH остаётся дополнительным способом; для основного прямого TLS-подключения ключ SSH не нужен.

Перед повторной проверкой убедитесь, что `systemctl is-active pepelaz-todo postgresql@16-main` возвращает active, а GET `/login/` по HTTPS возвращает `pepe1az`. Регулярно делайте резервную копию учебной БД и оставьте сервис включённым на период оценивания.
